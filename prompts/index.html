럭키 룰렛 바이브코딩 — 배포용 프롬프트

라이브 실습(카지노풍 럭키 룰렛 뽑기 앱)에서 바로 붙여넣을 프롬프트입니다. 도구(Claude Code·Codex·DeepSeek 등)마다 결과가 갈리던 효과는 걷어내고, 한 번에 안정적으로 나오는 범위로 좁힌 버전입니다.

1. 최종 프롬프트

아래 전체를 복사해 새 세션에 붙여넣으세요
"돌림판(랜덤 뽑기 룰렛)" 웹앱을 순수 HTML+CSS+JS 한 파일로 만들어줘. 프레임워크 없이, 구글 폰트만 CDN으로 써도 돼.

## 화면 구성 (반드시 두 화면으로 분리)
1) 참가자 준비 화면
   - 이름 입력창(Enter 또는 추가 버튼), 참가자 칩 목록(각 칩에 삭제 버튼)
   - "뽑힌 사람은 다음 판에서 제외" 체크박스
   - 초기화 버튼(제외 상태·기록 지우기), 최근 당첨 기록 리스트
   - 화면 하단에 "룰렛 무대로 이동" 버튼
   - 폭은 720px 정도로 제한해서 입력 폼처럼 아담하게
2) 룰렛 무대 화면
   - 참가자 관련 UI 없이 룰렛 + 스핀 버튼 + 결과 텍스트만 크게
   - "← 참가자 수정" 버튼으로 화면1로 복귀
   - 폭 제한 없이(가로 전체 사용), 룰렛 크기는 "컨테이너 가로폭"과 "화면 세로 높이의 약 68%" 중 더 작은 값 기준(`width: min(100%, 68vh, 780px)` 같은 식) — 세로 짧은 창에서 잘리지 않게

화면 전환은 hidden 속성 토글 + 0.3초 정도의 짧은 페이드만. 참가자 목록/localStorage는 화면1에서만 다루고 화면2는 그 상태를 이어받아 그리기만 함.

## 디자인 톤 — 은은한 조명의 카지노
- 라이트/다크 대응 없이 어둡고 차분한 단일 테마. 참가자 화면은 차분하게, 룰렛 무대 화면만 룰렛 위쪽에서 은은한 방사형 스포트라이트 글로우를 배경에 깔아서 대비를 줄 것.
- 룰렛 조각 색은 원색 대신 채도 낮춘 보석톤(가넷 레드, 에메랄드, 사파이어, 자수정, 앤티크 골드, 오닉스 블랙, 코퍼, 슬레이트 틸). 각 조각은 중심이 밝고 테두리가 어두운 방사형 그라디언트로 곡면처럼.
- 룰렛 테두리는 화려한 다중 링을 쌓지 말고 얇은 단색 테두리선 1~2px 정도로만 (여러 겹 box-shadow 금지 — 애니메이션과 결합하면 어긋나 보이는 버그의 원인이 됨).
- 룰렛 중앙에는 아주 단정한 작은 원형 허브 캡 하나만. 십자 장식이나 캐릭터 같은 복잡한 문양은 넣지 말 것.
- 제목/버튼: 한글 세리프(Noto Serif KR, 굵게). 작은 영문 라벨: 클래식 영문 세리프(Cinzel, 자간 넓게). 본문·목록·룰렛 라벨: 한글 산세리프(Noto Sans KR). 룰렛 조각 안 이름은 반드시 산세리프로.

## 스핀 애니메이션 (정확히 이 로직대로)
1. 스핀 시작 시 원형으로 빠르게 회전 시작.
2. 회전 진행률 약 70%~100% 구간 동안, 룰렛 전체가 잘리는 부분 없이 그대로 살짝 커짐(1배 → 약 1.15배 정도). 일부만 보이게 자르는 효과 아님 — 원 전체가 항상 다 보이는 상태로 크기만 커짐.
3. 그 확대된 상태를 유지한 채 감속하며 멈추고 결과 표시 + 컨페티.

구현 시 반드시 지킬 것:
- 캔버스(룰렛 그림)와 테두리를 반드시 같은 하나의 요소 안에 넣을 것(테두리를 별도 div로 분리하지 말 것) — 분리하면 확대될 때 테두리와 내용물이 따로 노는 것처럼 보이는 버그가 생김.
- 회전 각도는 절대 0으로 리셋하지 말고 스핀마다 계속 누적시킬 것(초기화하면 바퀴가 역방향으로 튕기는 버그 발생). 매번 목표각 = 현재각 + (6~8바퀴 추가 회전) + 당첨 조각 중앙까지 가는 최소 회전각으로 계산하고, 당첨 조각의 중앙이 화살표(포인터) 위치에 정확히 오도록 맞출 것.
- easeOutCubic 같은 감속 곡선을 쓰고, requestAnimationFrame으로 매 프레임 회전각·확대 배율을 다시 계산해서 그릴 것. CSS transition 속성은 이 요소에 걸지 말 것(매 프레임 값이 바뀌므로 충돌함).
- prefers-reduced-motion이 켜져 있으면 확대 배율은 1로 고정하고 회전만 재생할 것.

## 기타 기능
- 참가자 목록은 localStorage에 저장(try/catch로 감싸서 실패해도 안 죽게).
- 당첨 시 컨페티(색종이) 이펙트.
- 룰렛/컨페티 캔버스 크기는 항상 정사각형으로 맞춰서 비율이 틀어지지 않게 할 것.
- 모바일 폭(400px)에서도 안 깨지게 반응형으로.

2. 실행 방법

위 프롬프트를 복사해서, 사용 중인 바이브코딩 앱(클로드 코드, 커서, 코덱스 등)에 새 세션을 열고 그대로 붙여넣으세요. 한 번에 전체를 붙여넣고 실행하면 참가자 입력 화면부터 룰렛 애니메이션까지 만들어집니다.

  • 반드시 새 세션(새 대화)에서 시작하세요 — 이전 맥락이 섞이면 결과가 달라질 수 있어요
  • 결과가 하나의 HTML 파일로 나오면 더블클릭해서 브라우저로 바로 열어 확인할 수 있어요
  • 완성까지 보통 1~2분 걸리니, 진행 메시지가 뜨는 동안 기다려주세요

3. 문제가 생기면 (버그 대응법 5단계)

  1. 화면을 캡처하세요 — 스크린샷 한 장이면 충분합니다
  2. 기대했던 모습과 실제로 나온 모습을 각각 적어보세요
  3. 어떤 순서로 하면 같은 문제가 다시 나타나는지 재현 과정을 적어보세요
  4. 가능하다면 개발자도구 콘솔의 에러 메시지를 복사해서 함께 붙여넣으세요
  5. 한 번에 다 고치려 하지 말고, 요청 범위를 좁혀서 다시 요청하세요

개발자도구가 어렵게 느껴진다면 괜찮아요 — 1~3번만 잘 전달해도 대부분 해결할 수 있습니다.

4. 실습 중 막히면

  • 테두리와 원판이 따로 노는 것처럼 보이면: "테두리와 캔버스를 같은 하나의 요소 안에 합치고, 그 요소 하나에만 확대를 걸어달라"고 구체적으로 요청하세요.
  • 회전이 튕기듯 부자연스러우면: 회전각을 매번 0으로 리셋하지 말고 계속 누적시키라고 명시해서 다시 요청하세요.
  • 당첨 결과와 화살표 위치가 안 맞으면: 멈춤 위치 계산이 당첨 조각 중앙을 포인터 위치에 정확히 맞추는지 다시 확인해달라고 요청하세요.
  • 모바일에서 레이아웃이 깨지면: "400px 폭에서도 확인해달라"고 구체적인 폭 숫자를 집어서 재요청하세요.
  • 전반적인 원칙: 한 번에 너무 많은 요구를 넣지 말고, 안 되는 부분만 짧고 구체적으로 집어서 다시 요청하세요. "더 예쁘게" 같은 모호한 피드백보다 "이 요소 하나에만 이 transform을 걸어달라" 식의 지시가 훨씬 잘 먹힙니다.

5. 더 도전하고 싶다면 (심화)

시간이 넉넉하고 여러 번 대화하며 고칠 수 있다면 아래 두 가지를 추가로 요청해볼 만합니다.

  1. 테두리 여러 겹 금색 링: "진한 금 → 밝은 금 → 진한 금이 번갈아가는 box-shadow를 여러 겹 쌓아서 세공된 금속 베젤처럼" 만들어달라고 요청.
  2. 카메라 리클라인: "캔버스+테두리를 하나의 wrapper로 묶고, 그 wrapper에만 CSS scaleY로 눕히고, 바깥 wrapper에는 overflow:hidden + scale()로 확대하라"고 명시적으로 요청.

여러 겹 요소에 서로 다른 transform을 나누어 걸어야 해서 한 번에 제대로 만들 확률이 낮습니다. 스핀 버튼을 눌러 눈으로 확인하며 "이 부분만 이렇게 고쳐줘"라고 반복 요청하세요. 처음 만들 때는 기본 버전을 권장합니다.
